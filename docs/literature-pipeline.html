2. DSL 管线内部：数据变形记

以一个真实检索式为例，追踪数据在每一站怎么变形。

你写的检索式
AB='转基因/NEAR 5水稻'
↓
管线判断: 包含 '=' → 走 DSL 路径，进入阶段 1
↓
阶段 1 — CnkiLexer + CnkiParser
Token 拆分 → AST 树
Lexer 把文本切成 8 个 Token：
Word:AB → Equals:= → Quoted:'转基因/NEAR 5水稻' → End
Parser 检测引号内 /NEAR 5 → 识别为 ProximityNode(Near, 5)
生成 AST：Proximity(Left=转基因, Right=水稻, Kind=Near, Distance=5, Field=AB)
入: 文本 → 出: AST (1个 ProximityNode, 2个 TermNode)
↓
阶段 2 — QueryPlanner
DNF 展开 → rough query
ProximityNode 在 DNF 中被当作 AND 处理（两词必须同时出现）
rough query = "转基因 水稻"（纯关键词，丢掉 /NEAR 运算符）
生成计划：4 个引擎各执行 1 条 rough query
入: AST → 出: SearchPlan (4 providers x 1 query)
↓
阶段 3 — 5 个 Provider 并行
HTTP 请求 → 候选论文
每个 Provider 调用自己的 REST API（OpenAlex GET, Metaso POST, AMiner GET...）
搜回原始 JSON → 映射为 PaperRecord 对象
假设回到 200 篇候选
入: "转基因 水稻" → 出: 200篇 PaperRecord
↓
阶段 4 — LocalBooleanFilter
逐条执行 /NEAR 5 匹配
对每篇论文的 AB（摘要）字段：
1. 分句
2. 每句中找 "转基因" 和 "水稻"
3. 计算两词之间的单词数
4. 间隔 ≤5 → 通过；否则丢弃

位置运算符、词频、模糊匹配都在这一站生效。
搜索引擎拿到的只是 "转基因 水稻" 两个关键词，完全不知道 /NEAR。
入: 200篇 → 出: ~50篇（真正满足 /NEAR 5 条件）
↓
阶段 5 — PaperRecordMerger
DOI 去重 + 元数据合并
同一篇论文可能被 OpenAlex 和 Crossref 都搜到
→ DOI 相同的合并为一条，保留最完整的元数据
入: 50篇 → 出: ~35篇（去重后）
↓
阶段 6 — LiteratureRanker
多因子排序
引用数越高越好 x 年份越新越好 x 关键词匹配越多越好
→ 综合分数排序
入: 35篇 → 出: 35篇（已排序）
↓
输出
截取前 --limit 篇
如果 --limit 5，只取前 5 篇。
可通过 -o result.json 保存原始数据，再用 lit export 导出 Markdown/BibTeX。
最终: 5篇精读清单

3. 核心设计：宽搜 + 精滤

这是整条管线最重要的设计决策，用图说清楚。

问题

OpenAlex、Crossref 这些学术 API 不懂 CNKI 语法。你把 AB='转基因/NEAR 5水稻' 发给它，它要么报错，要么返回一堆无关结果。

解法：分两段

第一段：宽搜（5 平台 API）
管线的"搜"：把复杂 DSL 拆成纯关键词
AB='转基因/NEAR 5水稻'
拆成 → 转基因 水稻
发给每个 API
搜回 200 篇（广撒网，宁可多不可少）
第二段：精滤（本机 LocalBooleanFilter）
管线的"滤"：在 200 篇候选上
真正执行 /NEAR 5 的语义
逐句计算两词间隔 ≤5
留下 50 篇（真的满足 /NEAR 条件）
结论：所有高级运算符（#、%、/NEAR、/PREV、/SEN、/PRG、$N、%=）都只在你的电脑上执行。远程 API 只负责"多搜"，你的电脑做"精判"。这样既利用了各大平台的索引能力，又能执行它们不支持的复杂检索语法。

4. 搜索条件怎么给

方式一：直接写关键词（最简单）

不用学任何语法，直接写空格分隔的关键词。管线检测到没有 DSL 符号，自动走路径A。

沸石 缓释 肥料
zeolite slow release fertilizer
适用场景：快速扫一下某个方向有什么文献。中文关键词主要被 AMiner 和秘塔搜到，英文走 OpenAlex 和 Crossref。

方式二：DSL 精确检索 (CNKI 专业检索语法)

完整支持 CNKI 专业检索语法。参考文档：CNKI 专业检索表达式语法。

基础运算符：

符号意思例子
* 或 AND并且'A'*'B' 或 TI='A' AND AB='B'
+ 或 OR或者'A'+'B' 或 TI='A' OR AB='B'
- 或 NOT不包含'A'-'B' 或 TI='A' NOT TI='B'
()分组('A'+'B')*'C'

高级位置运算符（在引号内使用）：

符号意思在哪生效
#同一句中本地精滤
% (引号内)同一句中，前词在先本地精滤
/NEAR N同句，相隔不超过N字词本地精滤
/PREV N前词在先，相隔不超过N字词本地精滤
/AFT N前词在后，相隔超过N字词本地精滤
/SEN N同段中，句子间隔不超过N本地精滤
/PRG N全文相隔不超过N段本地精滤

匹配修饰符：

符号意思在哪生效
= 'str'精确/包含API宽搜 + 本地精滤
% 'str'模糊包含（词可分词匹配）本地精滤
%= 'str'相关匹配（仅SU字段）本地精滤
/SUB N第N位包含本地精滤
$ N词至少出现N次本地精滤
BETWEEN年度/引用范围本地精滤

实际例子：

# 位置检索：摘要中转基因和水稻同句出现，间隔不超过5个词
AB='转基因/NEAR 5水稻'

# 复杂布尔：钱伟长在清华或上海大学期间的文章
AU = '钱伟长' AND (AF ='清华大学' OR AF ='上海大学')

# 多字段+模糊+分组
AU ='钱伟长' AND AF='清华大学' AND (TI ='物理' OR AB % '物理')

# 词频：全文中"大数据"至少出现5次
FT='大数据 $5'

# 沸石项目检索式（与之前兼容）
SU=('沸石'+'斜发沸石'+'分子筛')*('缓释'+'控释'+'慢释')*('肥料'+'化肥'+'农肥')

字段速查：

字段含义适用场景
SU主题 (Title + Abstract + Keywords)绝大多数情况
TI标题只搜标题
AB摘要只搜摘要
KY关键词只搜关键词
FT全文全文检索（需全文数据）
AU作者找某个人
AF机构找某个机构
YE年份YE BETWEEN(2020,2025)
JN期刊名限定某本期刊
DOI文献唯一号精确找某一篇
CF被引频次CF BETWEEN(10,100)

参数作用默认

# 批量扫文件夹
nong lit batch C:\搜索文献\ -o C:\报告.md --limit 10

7. lit batch — 批量检索

适用于一个项目有多个研究方向，每个方向一条 DSL。

搜索文献的东西/
  ├── 矿物基材料.txt       ← 含两条 DSL
  ├── 土传病害防控.txt     ← 含两条 DSL
  ├── 环境安全性.txt       ← 含一条 DSL
  └── 草案.txt             ← 不含 DSL，自动跳过
nong lit batch 搜索文献的东西/ -o 报告.md --limit 10
# 文献检索报告
生成时间：2026-06-14

## 矿物基材料
### 沸石缓释体系
候选 99 篇 → 去重 6 篇 → 返回 10 篇
1. **沸石基缓释肥料的研究进展**. 石勤等. 2022. [metaso]
...
规则：batch 默认 recall 模式（中文搜英文不丢结果）。每条 DSL 独立跑。

8. 搜不出来怎么办

现象可能原因怎么解决
中文 DSL 搜不出结果strict 模式把中文词在英文摘要里比对不过加 --mode recall
返回 0 篇AND 条件太严* 换成 +，或拆成多条
AMiner 报错key 过期去 open.aminer.cn 换 token
秘塔报错key 不对或余额用完确认 mk- 开头，查余额
候选很多、返回很少正常现象放宽 DSL 条件
